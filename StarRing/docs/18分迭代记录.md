# 星环算力平台调度：18 分版迭代记录

第一版先把交互、对账和合法启动跑通，再建立后续版本都使用的对照数据。**18/100** 是当时用户反馈的正式成绩；本地数据来自保存下来的官方练习，不是正式隐藏测试。实现细节见[18 分版源码分析](18分策略总结.md)。

## 起点与取舍

最初采用「先粗估一条流程的净收益，再对当前作业挑机器」的办法。主要状态已经和题面对齐：按前驱完成情况推进就绪表，用租户路径维护配额和费用，启动时精确处理镜像与传输。候选机器只细算粗排前八台，先给在线调度留出时间预算。

## 当前选用的数据结构

| 数据结构名称 | 源码里的实现 | 对应策略 |
| --- | --- | --- |
| 正反邻接表 + 无序动态数组 | `pred`、`succ`、`ready`、`Machine::run` | 按完成事件推进依赖，只把已就绪作业送进排序。 |
| 双向循环链表 + 扁平二维索引表 | `Cache::prv`、`Cache::nxt`、`vector<Memo> memo` | 两级 LRU 维护真实缓存；按「机器 × 镜像」复用当前作业的精确拉取估价。 |
| 定长前八候选数组 | `array<Placement, 8> cand` | 对单个作业先粗排再细算，限制每次机器选择的开销；不保存后续整条流程的机架计划。 |

## 验证如何纠偏

一开始自制模拟器需要自行补齐未公开的作业时长，曾得到样例 1 利润 15,073；那是另一套时长下的结果，不能当成官方样例成绩。接上官方 TPJ 后，样例 0、1 的实际利润分别是 **1,408、6,780**。样例 0 最后一轮多发 `KILL` 也是合法调度，不能用是否逐行等于题面输出代替裁判。

| --- | ---: |
| 总收益 | 428,818,000 |

| 对账错误 / 对账数 | 0 / 177,110 |

| 选手进程本机 CPU 最大值 | 0.296875 秒 |

## 下一轮为什么换思路

数据说明这批用例里不是「对不上账」，而是花掉的钱比赚到的多。第一版常用最低 CPU 价估后续投入，没有充分把准备时占核、拉镜像和跨架传输算进去。下一轮因此先为整条流程选落点、算全程成本，再决定是否开工，而不是继续只调单个作业的排序权重。不能据此推断正式评测中每个未通过用例的原因。
