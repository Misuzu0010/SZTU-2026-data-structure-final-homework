# 星环算力平台调度：68 分版源码分析

第二版最重要的变化是：**先估完一整条流程，再决定要不要启动第一个作业。** 读本版请用本地封存的 `StarRing/baselines/score68/StarRing_阅读版.cpp`，不要把后续版本的优化套到这一版。对照数据见[68 分版迭代记录](68分迭代记录.md)。

## 1. 交互骨架没换

`run()` 仍然先处理事件，再回答对账，最后发出指令。`arrive()` 和 `release()` 用前驱计数推进就绪作业；`head()`、`account()` 沿租户祖先路径维护配额和账单。预测使用的缓存副本、估计时长和模拟费用都不会写入真实对账状态。赫夫曼解码换成逐位走树，但告警匹配和窗口计分规则没变。

## 2. `forecast()`：先挑几个值得细算的机架

每个机架先按 CPU 单价和已知跨架输入的传输费粗排，只对前四个调用 `plan()`。如果两个机架的估价接近，程序稍微偏向原来的机架，避免来回换位置。选定的 `anchor` 是流程后续作业的首选机架，不是把所有作业派给同一台机器。

`plan()` 复制一台代表机器和机架的缓存，按依赖顺序逐个估算未完成作业。还没启动的前驱暂按同机架产出；已完成或正在别处运行的前驱则按实际来源估计传输。程序把准备时占核的费用、正式运行费、传输费和仓库拉取费都纳入估算。整条流程的工期既不能短过最长依赖链，也不能短过总核时摊到机架和租户能提供的核数上所需的时间。最后倒着算出每个作业后面还有多少时间要用。

## 3. `schedule()` 和 `place()`：减少开工后做不完的流程

`schedule()` 估算租户及各级上级已经承诺了多少工作量，给新流程加一段等待。预计收益不足就不启动；作业数大于 12 时还要求成本和截止时间留有余量；超过 40 个作业的流程不进入调度候选。程序更愿意给已投入的流程收尾。若单作业流程光拉镜像就来不及，直接跳过这一轮的规划。

`place()` 有锚定机架时只在那一架找机器，并用精确的两级 LRU 拉取估价筛前八台，不再像第一版那样在机器粗排时用三层外推。真正启动前仍检查当下的空闲资源、配额和输入可达性。一个机架不通不代表全网不通，因此不会把这次失败记成所有机架都不可达。

## 4. 当前选用的数据结构

| 数据结构名称 | 源码里的实现 | 对应策略 |
| --- | --- | --- |
| 哈希表 + 正反邻接表 + 无序动态数组 | `unordered_map<int, int> jid`、`pred`、`succ`、`ready`、`Machine::run` | 沿用[第一版](18分策略总结.md)的事件驱动推进：`need` 归零才就绪，`pos` 支持交换删除。 |
| 带版本的距离矩阵 + 数组双向循环链表 + 扁平二维索引表 | `Net::route`、`Cache::prv/nxt`、`vector<Memo> memo` | 复用最短路和精确镜像估价；整条流程试算只改 LRU 副本。 |
| 二维动态数组 + 机架下标 | `vector<vector<int>> rackMachines`、`Flow::anchor` | 先为整条流程选机架，放置时在该架内选机器，尽量复用镜像和前驱输出。 |
| 三个并行动态数组 | `vector<double> finish`、`stage`、`charges` | 按作业下标保存预计完成时刻、阶段耗时和费用；顺着依赖估工期，倒着算后续路径。 |
| 租户索引数组 + 祖先路径数组 | `vector<double> committed`、`Tenant::path` | 累计各租户子树已开工流程的估计核时，给新流程加上祖先配额的等待。 |
| 按镜像索引的动态数组 | `vector<i64> quickest` | 每轮按镜像计算一次最短准备时间；若单作业流程光拉取就来不及，跳过整条规划。 |
| 动态机架候选数组 + 定长前八候选数组 | `vector<pair<double, int>> candidates`、`array<Placement, 8> cand` | 机架按粗估取前四细算；机器改用精确 LRU 估价筛前八，不再用三层外推。 |

这版解决了「只看眼前一笔钱」的问题，但没有预留未来机器。同一个便宜机架仍可能被很多流程同时选中，这就是 78 分版继续处理的地方。
