# 星环算力平台调度：78 分版迭代记录

第三版从 68 分封存版起步，最终只采用机架排队估计。**78/100** 来自用户对这份第三版源码的正式成绩反馈，区别于后续 `Run 541074` 的另一份 78 分源码。代码如何计算见[78 分版源码分析](78分策略总结.md)。

## 验证了哪些方向

68 分版知道一条流程有多长，却可能低估别人已经占去多少机架容量。本轮分别试了机架排队、改进时长预测、用更精细的镜像估价筛机架。先在同输入代表组比较，再对入选方案跑固定 100 组和压力，避免只凭小样例选择。

- **排队**：在同一批 16 组里，系数 0.25 的利润增量为 4,740,552，16 组全提高；0.50 和 0.75 的收益更低，未采用。
- **时长模型**：单独扩到 100 组提高 1.61%，但与排队组合后的总利润略低于只加排队，没有一起合入。
- **精确镜像粗排**：与排队组合后，100 组利润增幅达到 14.52%，但全规模压力 CPU 为 2.500000 秒。后续最小值缓存方案仍为 1.031250 秒，未达到 1 秒门槛。

## 当前选用的数据结构

| 数据结构名称 | 源码里的实现 | 对应策略 |
| --- | --- | --- |
| 两个 30 项定长数组 | `array<double, 30> rackDebt`、`rackCores` | 一张记积压核时，一张记在线总核数。每轮重建，新流程首次开工时立即补记积压，让后续选架能估算等待。 |
| 二维动态数组 + 机架下标 | `rackMachines`、`Flow::anchor` | 沿用整条流程的首选机架，并据此把积压归到对应机架，不另建一条机架队列。 |

## 同输入结果

| 指标 | 68 分版 | 78 分版 |
| --- | ---: | ---: |
| 100 组总收益 | 361,011,019 | 388,122,786 |
| 100 组总费用 | 188,487,371 | 194,645,900 |
| 100 组总利润 | 172,523,648 | **193,476,886** |
| 完成工作流数 | 70,154 | 73,306 |
| 选手进程本机 CPU 最大值 | 0.531250 秒 | 0.453125 秒 |

净利润增加 **20,953,238（12.15%）**，91 组提高、9 组下降，单组最大退步 88,751。这次不是少花钱，而是多花的费用换来了更多能完成的流程。两版均在固定 100 组中做到 177,110 道对账全对、零非法指令。78 分版官方样例利润为 1,408 和 9,679；5 组独立压力共 14,000 道对账全对，最大本机 CPU 为 0.734375 秒。这些计时不是所有合法输入的上界。
