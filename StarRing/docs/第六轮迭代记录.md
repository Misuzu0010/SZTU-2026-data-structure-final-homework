# 第六轮：按可用配额计等待，同机估算冷启动

基线是第五轮 16294 字节版，源码 SHA-256 为 `192906d3e1585190b9cf24bb118c0ba4d453e81d3426557ce907751d4343311d`，不是 Run 541074 的旧 78 分版。第六轮晋升门槛为：固定 100 组和留出 32 组各提升至少 2%，另留出 16 个新种子核验收益；官方样例、逐组对账、指令和独立压力都通过，所测每组的本机选手 CPU 不超过 1 秒。提交版仍按前文的更严条件 **严格小于 16384 ASCII 字节**。

## 核心策略

1. **只为实际短缺的配额计等待。** 原先新流程总会承担祖先路径上的排队估计，即使剩余配额足以支持它和现有任务并行。现在以 `预计剩余核时 / 预计工期` 估平均需核数，原等待惩罚乘以 `max(0, 1 - 路径剩余配额 / 平均需核数)`。资源不紧时不重复计租户队列；已开工流程和真实 `RUN` 的配额检查不变。路径扫描仍为 O(租户树深度)，增量为 O(1) 时间与空间。
2. **仓库费、拉取时间取自同一台可用机器。** 原粗排分别取两项最小，可能组合出不存在的机器。现在先用首个待运行作业的 CPU/内存需求筛机器，抽样三层按综合费用择机，再对胜者完整预演 LRU。新流程的机架精算从这台机器的缓存起步，使用前复查在线和资源；没有合适机器则回落到机架代表机。七 tick 缓存保持原键，新策略仍只精算前四架。一次缓存缺失检查 O(架内机器数) 个三层样本并预演一次镜像，不改变真实计费或传输。

## 同输入实验

| 官方 TPJ 集合 | 第五轮利润 | `quota_locality` 利润 | 增幅 | 升 / 降 |
| --- | ---: | ---: | ---: | ---: |
| 固定 100 组 | 199265701 | 204247146 | +2.50% | 66 / 34 |
| 第四轮留出 32 组 | 57109514 | 58777030 | +2.92% | 22 / 10 |
| 新种子 16 组 | 35531977 | 36883606 | +3.80% | 13 / 3 |

新 16 组从旧留出八类配置各取两项，只替换种子，先生成 [参数清单](../experiments/round06/fresh_manifest.json) 再运行。每组实际裁判输入逐一核对 SHA-256。固定组最差 `case082` 为 -147310，旧留出最差 `holdout006` 为 -116943，新种子最差 `fresh000` 为 -26931；总利润提高不是逐组全胜。单独 `quota` 在三套集上为 +2.34% / +2.29% / +3.32%，组合都更好，且更短五字节。

代表集其他方向保留为消融：按利润衰减排队 `marginal` +0.59%，扣除已运行核时 `remaining` +0.79%，把已付费用计入故障风险 `risk` +0.16%，改长流程成本阈值 `timing_model` +1.27%，同机局部性 `locality` +1.30%。按祖先分别计算的 `quota_path` 代表集逐组利润与 `quota` 相同；`quota_timing` 只比 `quota` 多 69701（约 0.14%），不单独晋升。局部性首次打包 16443 字节被拒绝，未拿超限程序跑结果。

补试 `quota_refresh`：放置重算时继续复用适配机器的暖缓存估计，并把估计准备期存回缓存以避免重复整除。第一次打包 16407 字节被拒，局部简化后为 16348 字节、样例通过；相比 `quota_locality` 仅在代表集多 69469（约 0.14%，9 升、6 降、3 平），未达到下一次显著增益门槛，不扩大到全量。

## 时限与正确性

- Windows MinGW C++17 严格编译。两个官方样例利润 **1408 / 9884**；148 组 TPJ 练习和样例共 **264900** 道对账全对、零非法，单组 CPU 最大 **0.453125 秒**。
- 8 组独立压力另有 22400 道对账全对、零非法；同一多来源夹具上第五轮对照 **0.843750 / 0.828125 秒**，候选依次 **0.843750 / 0.781250 / 0.906250 秒**。保留全部计时，不把单次最小值描述成整体提速。压力 `max_case` 的自制裁判利润下降 1012564，不计作官方成绩。
- [跨机架输出夹具](../experiments/round06/edge/README.md) 另测 1600 道对账、4 次合法启动。真实轨迹中依赖来自两架，零字节来源断链时未启动、恢复后在第三架启动；独立裁判确认按份取最大得到 6 tick，而不是把同源字节合并后得 7 tick。

可复现证据：`python -B homeworks/StarRing/experiments/round06/summarize.py --select quota_locality`。输出 [结构化汇总](../experiments/round06/summary.json) 绑定所有实际源码、程序、输入与原报告；失败分支日志留在各候选目录。没有进行 Linux 实机编译或 OJ 提交；本机 1 秒验收不能证明所有输入或正式机器的上限。在线未知真实时长、故障和隐藏利润目标，现有证据只支持本轮实验最优，不支持全局最优。
