# 星环算力平台调度：18 分版源码分析

这是第一版。它已经能正确维护交互状态，但在决定「一条流程值不值得跑」时，只用很粗的成本估计；真正算清费用的时候，往往只看眼前这个作业。读本版适合从本地封存的 `StarRing/baselines/score18/StarRing_阅读版.cpp` 入手。结果和后续取舍见[18 分版迭代记录](18分迭代记录.md)。

## 1. `run()`：维护裁判所见的状态

每 tick 先处理 `DONE`、`FAIL`、链路和配额等事件，再答 `ANS`，最后调度并输出 `END`。`arrive()` 把一条工作流的作业连续存下来，用 `need` 记录未完成前驱数。前驱完成后，`release()` 扣掉后继的 `need`；计数归零才允许进入就绪表。故障只让作业回到待运行，不算完成。

`head()` 沿租户到根的路径找最小的剩余核数。`account()` 用「账单常数 + 当前费率 × tick」表示累计费用，只有启动和释放时更新费率。`slack()` 用题目给的作业时长算最长依赖路径，不使用调度器预测的真实时长。

## 2. `schedule()`：先估整条流程值不值得投入

程序用已完成作业的实际时长修正同租户的估计。它看最长的一串依赖作业要跑多久，也看总核时摊到可用总核数上要多久，取两者较大值。这里用的是全场在线核数和租户配额，并没为整条流程挑好一个机架。

费用主要按「剩余计算核时 × 全场最低 CPU 单价」估。这不是已经确定能做到的价格。例如后续作业只能放在更贵的机房，或者需要重新拉镜像，实际费用就会更高。排名还偏向快到期、预计利润高或已经开工的流程，但不会预先逐步模拟后续作业。

## 3. `place()`：把当前作业放到一台合适的机器上

程序先用 `group()` 把输入按来源机架归并：字节数求和计费用，等待取单份输入最慢的发送时间。然后检查哪些机架可达，哪些机器有空闲核数和内存。机器较多时，先用缓存命中或三层镜像样本粗估拉取成本，只留下八台；再精确预演两级缓存，比较费用、时间和近期故障风险。

实际启动前仍会核对当下的配额、资源和输入可达性。`RUN` 一发出，就把资源、真实镜像缓存和账单更新好；过了有收益的时刻，运行中的作业会被 `KILL`，停止继续花钱。某个作业在所有机架都不可达时，程序会记住当前网络版本，等网络变化再试。

## 4. 当前选用的数据结构

| 数据结构名称 | 源码里的实现 | 对应策略 |
| --- | --- | --- |
| 哈希表 + 动态数组 | `unordered_map<int, int> jid`、`vector<Job> jobs`、`vector<Flow> flows` | 把裁判给的作业编号转成内部下标；同一流程连续存放，方便遍历。 |
| 正反邻接表 + 未完成前驱计数 | `vector<int> pred`、`succ`；`Job::need` | 完成作业时只通知直接后继；前驱全部完成才把后继加入就绪表。 |
| 无序动态数组 + 位置索引 | `ready`、`Machine::run`、`Job::pos` | 用末尾元素补位，常数时间移除已启动、已完成或中断的作业。 |
| 父指针树 + 祖先路径数组 + 撤销栈 | `Tenant::parent`、`Tenant::path`、`vector<pair<int, i64>> undo` | 沿祖先路径算配额和账单；`UNDO` 按后进先出恢复旧配额。 |
| 邻接表 + 二叉小根堆 + 带版本的距离矩阵 | `Net::g`、`heap`、`route`、`stamp` | Dijkstra 按源机架缓存最短路；链路或机房状态变了才重新计算。 |
| 数组实现的双向循环链表 | `Cache::prv`、`Cache::nxt` 和哨兵 | 机器和机架分别维护 LRU，命中后移到最近使用端，超容量就淘汰最久未用的层。 |
| 扁平二维索引表 | `vector<Memo> memo`，下标 `machine_id * I + image_id` | 复用当前作业的精确镜像估价；机器或机架缓存的版本变了，就重新预演。 |
| 赫夫曼树 + 四位查表 + AC 自动机 + 环形缓冲区 | `Logs::child`、`decode`、`ac`、`window` | 查表解码日志、一次扫描匹配告警词，再按时间桶扣掉过期分数。 |
| 动态候选数组 + 定长前八候选数组 | `vector<Candidate> queue`、`array<Placement, 8> cand` | 就绪作业分批排序；机器先按成本粗排，只对前八台精算收益和准备时间。 |

这版已经把「指令是否合法」和「做了能不能赚钱」分开。问题主要出在第二件事：一条流程必须全部做完才有收益，单次启动合算，不代表后续投入也合算。
