# 星环算力平台调度：68 分版迭代记录

第二版从 18 分封存版出发。官方练习已能对账且没有非法指令，主要问题是开工太多、收尾太少，花掉的成本拿不回来。本轮因此优先改规划和准入，不重写交互和账务。**68/100** 来自用户反馈的正式成绩。实现见[68 分版源码分析](68分策略总结.md)。

## 采用的方案

先粗选机架，再模拟整条流程剩下的准备、运行、传输和费用，最后决定是否启动。已投入的流程优先收尾；较长的流程要求更多余量。对于大量单作业流程卡在镜像准备的场景，按镜像复用同一轮的最快准备时间，不让每个流程都扫一遍机器。逐位赫夫曼解码用来给提交源码腾空间，是否仍在时限内则单独验证。

## 当前选用的数据结构

| 数据结构名称 | 源码里的实现 | 对应策略 |
| --- | --- | --- |
| 二维动态数组 + 机架下标 | `vector<vector<int>> rackMachines`、`Flow::anchor` | 为整条流程选首选机架，后续作业尽量留在同架。 |
| 并行动态数组 | `vector<double> finish`、`stage`、`charges` | 开工前沿依赖估出整条流程的工期和费用，不再只算眼前的作业。 |
| 按编号索引的动态数组 | `vector<double> committed`、`vector<i64> quickest` | 按租户汇总积压，按镜像缓存本轮最短准备时间；不拿试算值做真实对账。 |

## 同输入比较

两版使用同一批 100 组官方 TPJ 输入，逐组核对输入哈希。全部组的利润都提高，但收入不是越高越好：少做一些不划算的流程，省下来的费用远超过少赚的收入。

| 指标 | 18 分版 | 68 分版 |
| --- | ---: | ---: |
| 官方样例 0 / 1 利润 | 1,408 / 6,780 | 1,408 / 9,647 |
| 100 组总收益 | 428,818,000 | 361,011,019 |
| 100 组总费用 | 536,962,803 | 188,487,371 |
| 100 组总利润 | −108,144,803 | **172,523,648** |
| 亏损组 | 85 | 0 |
| 选手进程本机 CPU 最大值 | 0.296875 秒 | 0.531250 秒 |

两版在 100 组中均为 177,110 道对账全对、零非法指令。68 分版另在 5 组独立压力中通过 14,000 道对账，最大本机 CPU 为 0.796875 秒。压力使用独立模拟器，不当作官方评测；练习利润也不能换算正式得分。

## 保留的问题与证据

提高利润的代价是比第一版多算整条流程，练习耗时也更高。代表机器的缓存只能近似真实放置；此外，机架有多少在线核不等于这些核接下来都能分给当前流程。下一轮重点验证按机架估等待是否值得。
